# 4. Time and Space Complexity

## 4.1 Time Complexity

### Definition

**Time complexity** is a function that describes how the **execution time of an algorithm grows** with respect to the **size of the input**.

It does **not** measure actual time in seconds. Instead, it counts the **number of elementary operations** performed as input size increases.

Formally:

> Time complexity measures the order of growth of an algorithm’s running time as a function of input size *n*.

---

### Why We Ignore Actual Execution Time

Actual execution time depends on:

* Processor speed
* Compiler optimizations
* Programming language
* Operating system

DAA avoids these variables and focuses on **algorithmic growth behavior**, which is platform-independent.

---

### What Is Counted in Time Complexity

Typical basic operations include:

* Comparisons (`<`, `>`, `==`)
* Assignments (`=`)
* Arithmetic operations (`+`, `-`, `*`, `/`)
* Array access
* Loop iterations

---

### Example 1: Constant Time Algorithm

```text
x = a + b
```

* One operation
* Independent of input size

**Time Complexity:** `O(1)`

---

### Example 2: Linear Time Algorithm

```text
for i = 1 to n
   print(i)
```

* Loop runs `n` times

**Time Complexity:** `O(n)`

---

### Example 3: Quadratic Time Algorithm

```text
for i = 1 to n
   for j = 1 to n
      print(i, j)
```

* Inner loop runs `n` times for each outer loop iteration

**Time Complexity:** `O(n²)`

---

### Best, Average, and Worst Case Time Complexity

| Case         | Meaning               | Importance      |
| ------------ | --------------------- | --------------- |
| Best Case    | Minimum time required | Rarely useful   |
| Average Case | Expected time         | Hard to compute |
| Worst Case   | Maximum time required | Most important  |

**DAA focuses primarily on worst-case analysis**, because it guarantees performance bounds.

---

### Example: Linear Search

* Best Case: key found at first index → `O(1)`
* Worst Case: key at last index / not found → `O(n)`
* Average Case: `O(n)`

---

## 4.2 Space Complexity

### Definition

**Space complexity** is the total amount of **memory required by an algorithm** as a function of input size.

It includes:

1. **Input space**
2. **Auxiliary (extra) space**

---

### Space Complexity Formula

```text
Space Complexity = Fixed Space + Variable Space
```

---

### Fixed Space

Independent of input size:

* Constants
* Simple variables
* Program instructions

---

### Variable Space

Depends on input size:

* Arrays
* Dynamic memory
* Recursive call stack

---

### Example 1: Iterative Algorithm

```text
for i = 1 to n
   print(i)
```

* Uses only one variable `i`

**Space Complexity:** `O(1)`

---

### Example 2: Recursive Algorithm

```text
factorial(n):
   if n == 0 return 1
   return n * factorial(n-1)
```

* Each recursive call uses stack memory
* Depth of recursion = `n`

**Space Complexity:** `O(n)`

---

### Time–Space Trade-off

Often, improving time complexity increases space complexity.

Example:

* **Dynamic Programming**

  * Uses extra memory (tables)
  * Reduces repeated computation

This trade-off is a **core design decision** in algorithm design.

# 5. Asymptotic Notations

## 5.1 Purpose of Asymptotic Analysis

Asymptotic analysis studies **algorithm performance for large input sizes**, ignoring:

* Constants
* Lower-order terms
* Hardware details

It focuses on **growth rates**, not exact values.

---

### Example

Consider:

```text
T(n) = 3n² + 5n + 10
```

As `n → ∞`, lower terms become insignificant.

Asymptotically:

```text
T(n) = O(n²)
```

---

## 5.2 Big-O Notation (Upper Bound)

### Definition

**Big-O notation** provides an **upper bound** on the time or space complexity of an algorithm.

Formally:

> f(n) = O(g(n)) if there exist constants c > 0 and n₀ such that
> f(n) ≤ c·g(n) for all n ≥ n₀

---

### Interpretation

* Describes **worst-case performance**
* Guarantees that algorithm will not exceed a certain growth rate

---

### Example

```text
T(n) = 2n + 10
```

Asymptotically:

```text
T(n) = O(n)
```

---

### Common Big-O Classes

| Notation   | Meaning      |
| ---------- | ------------ |
| O(1)       | Constant     |
| O(log n)   | Logarithmic  |
| O(n)       | Linear       |
| O(n log n) | Linearithmic |
| O(n²)      | Quadratic    |
| O(2ⁿ)      | Exponential  |

---

## 5.3 Big-Ω Notation (Lower Bound)

### Definition

**Big-Ω notation** provides a **lower bound** on algorithm complexity.

Formally:

> f(n) = Ω(g(n)) if there exist constants c > 0 and n₀ such that
> f(n) ≥ c·g(n) for all n ≥ n₀

---

### Interpretation

* Best-case or minimum performance guarantee
* Shows algorithm cannot be faster than a certain rate

---

### Example

```text
Linear search best case = Ω(1)
```

---

## 5.4 Big-Θ Notation (Tight Bound)

### Definition

**Big-Θ notation** gives a **tight bound**, meaning both upper and lower bounds are the same.

Formally:

> f(n) = Θ(g(n)) if
> f(n) = O(g(n)) and f(n) = Ω(g(n))

---

### Interpretation

* Exact asymptotic growth rate
* Most precise notation

---

### Example

```text
T(n) = 3n + 5
```

Then:

```text
T(n) = Θ(n)
```

---

## 5.5 Little-o and Little-ω (Brief Conceptual View)

* **little-o (o)**: Strictly smaller growth rate
* **little-ω (ω)**: Strictly larger growth rate

Example:

```text
n = o(n²)
n² = ω(n)
```

These are used in **theoretical analysis**, less common in exams.

---

## Summary (Exam-Focused)

* **Time Complexity:** Growth of execution time
* **Space Complexity:** Growth of memory usage
* **Big-O:** Upper bound (worst case)
* **Big-Ω:** Lower bound (best case)
* **Big-Θ:** Tight bound (exact growth)
* Constants and lower-order terms are ignored
* Focus is on scalability
