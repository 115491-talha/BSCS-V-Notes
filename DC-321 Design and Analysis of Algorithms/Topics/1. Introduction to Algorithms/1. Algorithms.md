## 1. Algorithms

### Definition

An **algorithm** is a **finite, well-defined sequence of unambiguous steps** that takes some input, processes it, and produces a correct output to solve a specific computational problem.

In simpler terms:

> An algorithm is the *logic* behind a program, independent of any programming language.

---

### Key Characteristics of an Algorithm

A valid algorithm must satisfy the following properties:

1. **Input**
   Accepts zero or more inputs from a defined domain.

2. **Output**
   Produces at least one output.

3. **Definiteness**
   Each step is clear, precise, and unambiguous.

4. **Finiteness**
   Terminates after a finite number of steps.

5. **Effectiveness**
   Each step must be basic enough to be executable in finite time.

---

### Example 1: Algorithm to Find Maximum of Two Numbers

**Problem:** Find the maximum of two integers `a` and `b`.

**Algorithm:**

1. Read `a` and `b`
2. If `a > b`, output `a`
3. Else, output `b`
4. Stop

This algorithm:

* Has input (`a`, `b`)
* Produces output (maximum)
* Terminates
* Has unambiguous steps

---

### Algorithm vs Program

| Algorithm              | Program                   |
| ---------------------- | ------------------------- |
| Language-independent   | Language-dependent        |
| Focuses on logic       | Focuses on implementation |
| Abstract               | Concrete                  |
| Designed before coding | Written after algorithm   |

---

### Importance of Algorithms in Computing

Algorithms are central to computer science because:

* They determine **efficiency**
* They influence **scalability**
* They impact **resource usage**
* They enable **problem-solving at scale**

For example:

* Google Search → ranking algorithms
* Databases → indexing and query optimization algorithms
* OS → scheduling algorithms
* Compilers → parsing and optimization algorithms

## 2. Analysing Algorithms

### Definition

**Algorithm analysis** is the process of determining the **computational resources** (primarily **time** and **space**) required by an algorithm as a function of input size.

The goal is **not** to measure actual runtime, but to:

* Compare algorithms
* Predict performance
* Choose the most efficient solution

---

### Why We Analyse Algorithms

We analyze algorithms to:

* Compare multiple solutions to the same problem
* Understand scalability
* Avoid inefficient designs
* Make informed design decisions

Example:

* Bubble Sort vs Merge Sort
  Both sort arrays, but their performance differs drastically for large inputs.

---

### Types of Algorithm Analysis

#### 1. **Time Complexity**

Measures the number of **basic operations** performed by an algorithm.

Examples of basic operations:

* Comparisons
* Assignments
* Arithmetic operations

#### 2. **Space Complexity**

Measures the amount of **extra memory** used by an algorithm (excluding input).

---

### Case Analysis

Algorithms are usually analyzed under different cases:

1. **Best Case**

   * Minimum time required
   * Rarely used for decision making

2. **Average Case**

   * Expected performance
   * Often difficult to compute

3. **Worst Case**

   * Maximum time required
   * Most important for guarantees

---

### Example: Linear Search

```text
for i = 0 to n-1
   if arr[i] == key
      return i
```

* **Best Case:** `O(1)` (key at first position)
* **Worst Case:** `O(n)` (key not present or at last position)
* **Average Case:** `O(n)`

---

### Input Size Consideration

Input size depends on the problem:

* Array → number of elements `n`
* Matrix → rows × columns
* Integer → number of digits
* Graph → vertices + edges

## 3. Efficiency of an Algorithm

### Definition

The **efficiency of an algorithm** refers to how well it uses **time and memory resources** as the input size grows.

Efficiency is typically expressed using **asymptotic notations**.

---

### Why Efficiency Matters

An inefficient algorithm may:

* Work for small inputs
* Fail for large inputs
* Consume excessive memory
* Become impractical in real systems

Example:

* `O(n²)` algorithm for `n = 10⁶` is infeasible
* `O(n log n)` may still be practical

---

### Time Efficiency

Focuses on how execution time grows with input size.

| Growth Rate  | Name         |
| ------------ | ------------ |
| `O(1)`       | Constant     |
| `O(log n)`   | Logarithmic  |
| `O(n)`       | Linear       |
| `O(n log n)` | Linearithmic |
| `O(n²)`      | Quadratic    |
| `O(2ⁿ)`      | Exponential  |

---

### Example: Efficiency Comparison

#### Algorithm A

```text
for i = 1 to n
   print(i)
```

Time Complexity: **O(n)**

#### Algorithm B

```text
for i = 1 to n
   for j = 1 to n
      print(i, j)
```

Time Complexity: **O(n²)**

As `n` increases, Algorithm B becomes drastically slower.

---

### Space Efficiency

Concerned with extra memory usage.

Example:

* Recursive algorithms often use **stack space**
* Dynamic programming trades space for time

---

### Trade-off Between Time and Space

Often, improving time efficiency increases space usage.

Example:

* Memoization reduces time but uses extra memory
* Iterative solutions use less stack space than recursion

---

### Practical Efficiency vs Theoretical Efficiency

* Theoretical: Asymptotic analysis
* Practical: Hardware, cache, compiler, constants

In DAA, **asymptotic efficiency dominates**, because it reflects scalability.

---

## Summary (Exam-Friendly)

* **Algorithm:** Step-by-step method to solve a problem
* **Algorithm Analysis:** Study of time and space requirements
* **Efficiency:** How performance scales with input size
* **Worst-case analysis** is most significant
* Efficient algorithms are critical for real-world systems
