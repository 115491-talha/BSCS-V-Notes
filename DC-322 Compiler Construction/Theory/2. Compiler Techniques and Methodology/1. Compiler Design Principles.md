# 2. Compiler Techniques and Methodology

Compiler techniques and methodology deal with the **principles, strategies, and engineering approaches** used to design, implement, and evolve compilers efficiently.

---

## 2.1 Compiler Design Principles

Compiler design principles are **guidelines** that help in building **correct, efficient, maintainable, and portable** compilers.

---

### 2.1.1 Modularity

**Principle**
A compiler should be divided into **independent phases**, each responsible for a specific task.

**Why it matters**

* Easier debugging
* Independent testing
* Phases can be replaced or improved without affecting others

**Example**

* Replace a recursive-descent parser with an LL(1) parser
* Keep lexical analyzer unchanged

---

### 2.1.2 Separation of Front End and Back End

**Front End**

* Language dependent
* Performs:

  * Lexical analysis
  * Syntax analysis
  * Semantic analysis
  * Intermediate code generation

**Back End**

* Machine dependent
* Performs:

  * Code optimization
  * Target code generation

**Advantage**

* Same front end → multiple machines
* Same back end → multiple languages

```
Source Language → Front End → IR → Back End → Target Code
```

---

### 2.1.3 Machine Independence

**Principle**
Compiler should minimize machine-specific details in early phases.

**How**

* Use intermediate representations (IR)
* Delay hardware assumptions until code generation

**Benefit**

* Portability
* Retargetability

---

### 2.1.4 Efficiency (Time and Space)

A good compiler:

* Produces **fast code**
* Uses **reasonable compilation time**
* Uses memory efficiently

**Trade-off**

* Aggressive optimization ↔ longer compilation time

---

### 2.1.5 Error Detection and Recovery

**Principle**

* Detect errors as early as possible
* Continue compilation after errors (where possible)

**Example**

* Syntax error recovery using panic-mode
* Semantic error reporting with line numbers

---

### 2.1.6 Simplicity and Maintainability

* Clear grammar
* Clean IR
* Well-defined interfaces between phases

This is why **real-world compilers evolve for decades** (e.g., GCC, LLVM).
