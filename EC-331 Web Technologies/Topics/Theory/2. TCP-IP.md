## 2. TCP/IP

### 2.1 Overview of TCP/IP Model

The **TCP/IP model** is a layered network model used for communication over the Internet.

| Layer          | Purpose                      |
| -------------- | ---------------------------- |
| Application    | User-level services          |
| Transport      | End-to-end communication     |
| Internet       | Logical addressing & routing |
| Network Access | Physical data transmission   |

This model is simpler and more practical than OSI and is **actually implemented** on the Internet.

---

### 2.2 Application Layer Services

The **Application Layer** provides services directly to user applications.

#### Common Services

* **HTTP/HTTPS** – Web communication
* **FTP** – File transfer
* **SMTP** – Sending emails
* **POP3 / IMAP** – Receiving emails
* **DNS** – Domain name resolution

**Important Note**
The application layer does **not** mean user interface; it defines **communication rules** for applications.

---

### 2.3 HTTP Protocol Basics

**HTTP (HyperText Transfer Protocol)** is a **stateless, request–response protocol** used for communication between web clients and servers.

#### Characteristics

* Stateless (each request is independent)
* Text-based
* Runs on TCP
* Default ports:

  * HTTP → 80
  * HTTPS → 443

#### Common HTTP Methods

| Method | Purpose       |
| ------ | ------------- |
| GET    | Retrieve data |
| POST   | Submit data   |
| PUT    | Update data   |
| DELETE | Remove data   |

**Example**

```
GET /index.html HTTP/1.1
Host: example.com
```

---

### 2.4 Request–Response Model

The **Request–Response Model** is the foundation of web communication.

#### Step-by-step Flow

1. Client sends an HTTP request
2. Server receives and processes it
3. Server sends back an HTTP response
4. Client renders the response

#### HTTP Response Structure

* Status Code (200, 404, 500)
* Headers
* Body (HTML, JSON, etc.)

**Example**

* Request: User clicks “Login”
* Response: Server returns authentication result

**Common Status Codes**

| Code | Meaning               |
| ---- | --------------------- |
| 200  | OK                    |
| 301  | Moved Permanently     |
| 400  | Bad Request           |
| 401  | Unauthorized          |
| 404  | Not Found             |
| 500  | Internal Server Error |

## Conceptual Bridge (Why This Matters)

* **Web applications** sit at the top of the stack
* **TCP/IP** ensures reliable communication underneath
* HTTP acts as the **contract** between client and server
* Client–server architecture enables scalability and security
* Modern frameworks are abstractions over these fundamentals
