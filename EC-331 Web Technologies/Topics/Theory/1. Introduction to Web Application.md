## 1. Web Applications

### 1.1 Definition of a Web Application

A **web application** is a software application that runs on a **web server** and is accessed by users through a **web browser** over a network (typically the Internet) using standard web protocols such as HTTP/HTTPS.

**Key characteristics**

* No local installation required (browser is enough)
* Platform independent
* Centralized updates and maintenance
* Uses web technologies (HTML, CSS, JavaScript, backend languages)

**Examples**

* Gmail
* Facebook
* Online banking systems
* Learning Management Systems (LMS)
* GitHub

---

### 1.2 Web Application vs Desktop Application

| Aspect               | Web Application          | Desktop Application       |
| -------------------- | ------------------------ | ------------------------- |
| Installation         | No installation required | Must be installed locally |
| Platform Dependency  | Platform independent     | Platform dependent        |
| Access               | Via browser              | Via OS executable         |
| Updates              | Centralized on server    | Manual or updater-based   |
| Internet Requirement | Usually required         | Optional                  |
| Data Storage         | Server-side (cloud)      | Local machine             |
| Scalability          | High                     | Limited                   |

**Example**

* Web App: Google Docs
* Desktop App: Microsoft Word (offline version)

**Insight**
Modern applications often use a **hybrid model**, e.g., Electron apps (VS Code), which are desktop shells around web technologies.

### 1.3 Client–Server Architecture

**Client–Server Architecture** is a distributed model where:

* **Client** requests services
* **Server** processes requests and returns responses

#### Components

1. **Client**

   * Web browser (Chrome, Firefox)
   * Sends HTTP requests
2. **Server**

   * Web server (Apache, Nginx)
   * Application server (Node.js, ASP.NET, Java)
   * Database server (MySQL, PostgreSQL)

#### Flow (Conceptual)

```
Client (Browser)
   ↓ HTTP Request
Web Server / Application Server
   ↓ Process Logic
Database
   ↑ Data
Server
   ↑ HTTP Response
Client
```

**Advantages**

* Centralized control
* Better security
* Scalable architecture

**Real-life analogy**
Customer (client) orders food → Restaurant kitchen (server) prepares → food is delivered (response).

### 1.4 Evolution of Web Applications

#### 1. Static Web (Web 1.0)

* Fixed HTML pages
* No user interaction
* Read-only content

**Example**: Early informational websites

---

#### 2. Dynamic Web Applications

* Server-side scripting introduced
* Content generated dynamically
* Forms, databases

**Technologies**

* PHP, ASP.NET, JSP
* MySQL, SQL Server

**Example**

* Login systems
* Online forms

---

#### 3. Rich Internet Applications (RIA)

* Client-side scripting dominance
* AJAX enabled partial page updates

**Technologies**

* JavaScript
* jQuery
* AJAX

**Example**

* Google Maps (dynamic updates without refresh)

---

#### 4. Modern Web Applications

* SPA (Single Page Applications)
* REST APIs
* Cloud-native

**Technologies**

* React, Angular, Vue
* REST, GraphQL
* Microservices

**Example**

* Gmail
* Trello
* Notion
